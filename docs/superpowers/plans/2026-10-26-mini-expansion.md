# Mini风格安卓扩展实施计划

**Goal:** 用户明确要求增加枪械、配件，并使用其Mini源码的操作设计、视角、环境和大地图。只导出Android arm64。
**Architecture:** 维持权威World数据；新增Catalog集中装备参数与图集映射、WorldMap生成确定性大地图、MapScreen显示探索与标记。移植源码中的移动/举枪状态、停步缩准、移动散布、武器差异，不直接连接原工程的单例和UI。
**Spec:** 本轮用户新增要求优先于初稿MVP数量边界；原文档的营地、统一时钟、所有权和死亡规则继续保留。

- [x] 审核用户本地minidayz-master.zip：已发现环境60px图块、建筑外观/室内、武器分向图集、枪械图标和配件图集。资源仅用于用户个人离线使用，记录原来源状态，不改称开放商用资源。
- [x] catalog.gd与rules.gd：16枪/14配件，弹药分类、接口兼容、射程/噪声/换弹/散布/容量效果；test_expansion.gd先验证数量、效果及守恒。
- [x] world_map.gd：8×8街区、10240×8960连续探索区，初始三建筑坐标保留，新增确定性建筑、道路与河流桥梁；分区加载只绘制/模拟附近内容。
- [x] world.gd：新军械箱与大地图容器固定生成、探索记录、旧档一次性扩充、有效所有权检查和保存。
- [x] game.gd/hud.gd：独立开火、停步瞄准、武器轮换、横屏触摸热区；多枪装备/配件卡片、可缩放地图与目标点。保持各触摸ID独立。
- [x] mini图集接入世界、建筑、枪械图标和持枪姿态。摄像机以玩家为中心，扩大可视范围。
- [x] 跑原回归与新增行为测试；实际渲染截图；独立审查关键问题；只导出arm64 APK，验证签名、ABI与素材完整性。

主要风险：远处建筑不能漏碰撞、原有死亡回收与装拆仍须守恒、同口径不得混用、旧档不能重复领取新内容、界面必须可滚动而不溢出、地图目标只导航不传送。
