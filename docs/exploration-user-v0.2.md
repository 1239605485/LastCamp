# 末日营地：安卓像素生存游戏开发设计文档

版本：v0.2（自由探索修订稿）  
日期：2026-10-26  
项目名称：末日营地（沿用工作代号，正式名称待定）  
平台：Android，横屏，优先 arm64  
基础工程：LastCamp v0.5；本次只修订设计文档，不表示相关玩法已实现。

## 1. 本次修订与使用规则

本版根据本次讨论，将主线由固定营地经营、每晚守家，改为在持久化大地图中探索、搜刮、寻找住所，并发现和前往新地区。玩家可以长期住在自己选中的房屋，也可以携带必要物资不断迁移。

取消系统指定的固定基地、核心血量、定时返营和每晚强制攻营地。保留昼夜、生存、枪械配件、建筑搜刮、家具搬运、同伴救援及死亡遗物回收，并重新安排它们在自由探索中的作用。

本文区分三类状态：

- **本次修订方向**：自由探索、发现新地区、取消强制固定基地；是用户要求本次改稿所依据的方向。
- **沿用需求**：安卓小人物像素表现、主动射击、可进入建筑、配件、家具与救援等既有要求。
- **建议默认／后续候选**：为闭合规则提出的具体方案；数值、复活位置、模拟范围和阶段划分仍可调整，不等同全部细节均经用户逐条确认。

本版替代 v0.1 的冲突规则；开发者不能继续同时执行“夜间必须守核心”和“无固定基地”。设计目标、当前源码能力与实测结果必须分别记录。

## 3. 核心体验与逻辑调整

玩家根据缺少的物资决定目的地，在搜刮中评估噪声、负重、伤势和天色；遭遇危险时可以战斗、绕行或甩脱；疲劳时寻找房屋过夜，次日沿线索进入新地区。成长体现为更好的装备、更多地图信息、可靠住所和处理风险的能力。

| 旧规则 | 本版替代 | 必须处理的关联 |
|---|---|---|
| 固定核心屋、北墙与守家失败 | 住所属于普通世界建筑，失守后可撤离 | 删除核心失败判定和强制夜战UI |
| 每晚定时尸潮 | 游荡尸群、声源调查和有预兆的世界事件 | 不能改成无预兆贴身刷怪 |
| 回基地睡觉、修理、交易 | 与世界中的床位、工作台、商人对象交互 | 功能不能继续判断旧营地坐标 |
| 全局仓库与军械箱 | 每个真实容器有独立库存和位置 | 不允许跨地图远程取物 |
| 固定营地复活 | 登记落脚点恢复，危险时选择有效备用点 | 全部遗物保留，避免无限死循环 |
| 同伴自动撤回营地 | 约定会合点、可达撤退或原地待救 | 不瞬移、不因跨区恢复满血 |
| 家具带回营地 | 家具可放到任意有效地点 | 唯一实例、空容器打包和碰撞保持一致 |

## 4. 世界结构与发现新地图

### 4.1 建议结构

采用“区域内连续探索＋区域之间明确出口＋统一时钟”。不为本次改版重写为无限无缝世界。每个地区包含多个聚落、道路、野外和特殊地点，附近区块加载完整实体，远处降频或休眠。

现有源码已有按种子生成的区域大地图、道路、聚落和发现记录，可作为起点；跨地图入口、独立区域状态和切图事务需要新增。文档不把现有大地图内的聚落发现误写成已经支持跨地图旅行。

### 4.2 发现与通行

- 玩家通过步行探索、路牌、旧地图、字条、广播或NPC获知新地点。
- 区分“听说过”“发现入口”“已进入”，传闻不能直接揭示全部地形与容器。
- 初期地区建议包括小镇与林区两张地图；后续再扩工业区、城市和军事设施。
- 多数普通道路开放通行；少数特殊出口可要求钥匙、工具或修复，不把所有探索锁成线性任务链。
- 出口可以是公路、山口、隧道或渡口。目标地图首次进入时生成并保存；返回不重新抽取地图与物资。
- 每条连接保存来源和目标入口。往返位置明确，禁止随机落入墙内、水域或敌群。
- 切图不清除敌人警觉：近距离追击未解除时暂不能旅行，并提示原因；不把地图边界作为无成本脱战按钮。
- 转场耗时集中配置，按统一时钟只扣一次，不按地图实际像素距离暗自补扣。

### 4.3 地区差异

| 地区 | 核心收获 | 路线取舍 |
|---|---|---|
| 小镇 | 食物、基础工具、药品、家具 | 建筑多，室内可能藏敌 |
| 林区 | 采集、水源、稀疏住所 | 补给点远，需规划水和疲劳 |
| 工业区 | 零件、燃料、维修设施 | 空旷路段与封闭厂房交替 |
| 城市 | 多样物资与情报 | 尸群较密，枪声后撤离更难 |

只完成前两类验证跨区玩法，其余为内容扩展目标。

## 5. 时间、暂停与完整探索循环

1. 查看物资、伤势、疲劳和已知线索，决定当天目的地。
2. 沿道路或野外探索，搜刮、救援、取得工具和情报。
3. 根据敌人、天气和负重选择继续、绕行或返回某处住所。
4. 天黑前准备落脚点，也允许继续夜行；没有固定返程期限。
5. 在床位或睡袋休息，治疗与整理物资，次日继续探索。

建议原型一昼夜约30分钟，具体节奏通过实机调整。全世界统一时钟；入屋、切图、恢复和读档不重置昼夜与事件。天亮不删除存活敌人。

单人背包、地图、配件、系统菜单等完整面板暂停全世界。快捷切枪、同伴短指令不暂停。搜刮、制作、救援等在恢复世界后耗时完成；暂停内部整理不推进世界操作。手机后台、锁屏和退出期间停止世界时间，不按现实时间补扣资源。

## 6. 建筑、门窗与搜刮

### 6.1 建筑与物资

民居主要提供食物、衣物和家具；商店提供饮水、电池和工具；诊所提供药品；警务点提供有限枪弹；维修站提供零件、燃料和设施。武器不应平均出现在每种建筑里。

第一阶段沿用单层建筑；进入后隐藏屋顶，遮挡墙淡出。表现变化不改变碰撞，未观察的房间不能自动揭示敌人。容器首次生成即保存，重复进出和读档不重新刷取。

加入少量建筑状态组合：封窗房、搜空商店、留下工具的维修屋、屋内藏敌及求救字条。不同状态需要可见线索，罕见物资并非每次必出。

### 6.2 门窗互动（优先）

- 门具有开关、锁定、损坏和加固状态，破坏后状态持续保留。
- 允许正常开门、工具撬门或强行破门；时间和噪声不同。
- 窗户具有完好、破损、残留玻璃、加固状态；清理玻璃后可安全翻越，直接翻碎窗有受伤风险提示。
- 木板加固可拆除或受击破坏，不能形成不可摧毁的永久安全圈。
- 窗帘遮挡视线，不能当作实体墙阻挡通行；不完全隔绝声音。
- 行动有进度，移动或受击可中断；工具与材料只按已完成结果消耗。

### 6.3 触屏情境交互

靠近显示对象名称、动作、工具和预计耗时。多个对象重叠时可切换目标或打开附近列表，不能因目标漂移误丢装备。禁止隔墙搜刮；确认和完成时都检查距离、可达性、归属及容量。

### 6.4 物品转移事务

暂停中选择待执行的取物、存物、配件或打包请求，物品仍归原容器。开始执行后恢复世界，每项完成再校验并一次性提交。已完成项保留；移动、受击或取消只中断未完成项。容量不足停止队列并提示，不自动把多余物品丢到地面。第一阶段队列只针对一个附近容器。

## 7. 生存状态、睡眠与死亡

### 7.1 状态分层

| 状态 | 作用 | 阶段 |
|---|---|---|
| 生命、饥饿、口渴、负重 | 基本生存与携带取舍 | 第一阶段 |
| 体力 | 奔跑、近战等短时消耗，停下可恢复 | 第一阶段 |
| 疲劳 | 长期清醒累积，主要靠睡眠恢复；影响体力恢复和操作 | 第一阶段 |
| 流血 | 持续失血，可包扎 | 第一阶段 |
| 腿伤、疼痛 | 分别影响移动与瞄准，提供明确治疗提示 | 第二阶段 |
| 寒冷、淋湿 | 随气候内容扩展，屋内与衣物有作用 | 后续 |

体力与疲劳使用不同数值和提示。避免多项状态同时重复扣速导致无法恢复。第一阶段不做全身部位医疗、复杂疾病或默认必死感染。

### 7.2 睡眠

可在世界床位或已放置睡袋休息，不要求登记住所才能睡觉。睡眠前检查近处敌人、追击和入口威胁，并显示风险；床比地面更舒适。睡眠可加速世界，但周边威胁同步结算，不能跳过攻击。

撞门、近距离威胁、受击或主动取消会唤醒；加速倍率立即恢复。敌人能沿实际路径接近，不在床边凭空生成。睡眠、转场和伤后恢复共用时间推进服务，避免各自重复扣时。

### 7.3 死亡与恢复（建议默认）

所有随身物品转入死亡处唯一遗物容器，包括衣物、装备、背包内容、快捷栏、枪内子弹、配件和打包家具。保留实例ID和装配关系，背包清空与遗物创建在同一事务完成。

普通模式从已登记落脚点中选择有效恢复点；建议恢复经过1个游戏小时。不是世界回档，物资不刷新，旧遗物仍保留并标注地图；多次死亡不覆盖旧遗物。所有地点采用同一掉落规则，不再区分营地内外。

恢复点需要仍有有效床位、可站立位置且附近无直接威胁。若首选失效，依次提供其他登记点；全部失效时采用当前地区预设的备用恢复位置，并在恢复时检查及确保局部站位与出口可用，不删除整片地区敌人或重置地图。此项属于容错规则，不是新的固定基地。

不按每次死亡发放可出售装备；基础徒手或简易工具路径必须能重新取得最低生存资源。独立储物容器不因个人死亡清空。永久死亡仅作为后续可选难度，不和普通模式混用。

## 8. 枪械、配件和战斗


### 8.1 战斗操作（建议默认）

左侧摇杆移动，右侧瞄准并开火，提供开关式轻度辅助瞄准；投掷、换弹、切枪、互动使用少量独立按钮。辅助瞄准不能隔墙锁定，近距离交互优先级与战斗分开。

近战用于节省弹药并处理落单敌人，具有距离、攻击间隔和体力成本。枪械用于处理紧急威胁和尸群；其声音产生新的风险。

### 8.2 弹药规则（建议默认）

首版采用“枪内弹药＋背包中同口径散装弹药”。玩家执行换弹时消耗散装弹药补入枪内，不管理多个独立弹匣的剩余子弹。配件中的弹匣是改变容量/换弹等属性的实体配件。

中断换弹不扣除未实际装入的弹药。切枪、死亡、掉枪后不自动装满。写实弹匣可作为后续规则，不与首版并行开发。

### 8.3 配件槽

| 配件槽 | 第一阶段功能 | 约束 |
|---|---|---|
| 枪口 | 消音器、制退器 | 不同枪口规格兼容；消音不是完全无声 |
| 瞄具 | 红点、低倍镜 | 改善瞄准或观察，不揭示遮挡后的敌人 |
| 弹匣 | 扩容、快速弹匣 | 只改变枪械相关属性，不凭空产生弹药 |
| 下挂 | 握把、手电 | 对稳定性、照明等产生不同作用 |

MVP 先实现枪口与弹匣两类，其他槽保留设计位置。兼容性由枪械定义和接口标签共同控制，不靠配件名称字符串猜测。

### 8.4 装配事务与边界

- 安装前检查接口、占用槽、物品所有权和操作条件。
- 首版不堆叠多份同槽配件，不同时生效互斥配件。
- 拆下扩容弹匣时，超出新容量的枪内弹药退回背包；空间不足则阻止操作并解释原因。
- 交换配件时先检查被换下物品的存放空间，成功后一次性提交。
- 装配界面暂停，但确认装配后需要在世界中完成操作；战斗中被打断不产生半装配、双重属性或丢件。
- 耐久和维修属于后续阶段；MVP 不先引入卡壳、独立枪管磨损和全武器品质词条。


## 9. 幸存者与救援

保留招募与培养，改为医疗、维修、搬运和警戒等专长。第一阶段最多带一名同伴，以跟随、等待、撤退、救援和开火许可为基本指令；不做复杂多人生产排班。

健康→负伤→倒地待救→救起且负伤→在安全床位休养→恢复。救援建议约4秒，受击、移动或距离变化会中断；完成才消耗医疗物资。倒地不因计时归零永久删除，也不在跨区后自动治好。

玩家死亡后，能行动的同伴尝试前往约定会合点，必须有已知且可达路线；不能跨未知地图瞬移。找不到路线则就近停留并留下最后位置。倒地同伴保留原地待救标记。未加载地区记录撤退进度和位置，不在现场与离屏同时推进。

同伴拥有独立装备和库存，不因玩家死亡复制或掉落。商人和其他幸存者分布在世界中，不要求全部招募；交易受各自库存约束。

## 10. 自选住所、尸群与世界变化

### 10.1 落脚点

普通可用房屋可以睡觉、储物、封窗与摆放家具；“登记落脚点”只用于命名、地图标记、会合和恢复位置，不自动清空敌人、刷新资源或赋予无敌保护。允许多个落脚点，选择一个首选恢复点；可以取消登记，取消不删除已存物品。

住所内的储物、床、工作台和电器各自有真实世界位置。无全地图共享仓库，不允许远程取箱中物品。设施功能通过对象类型和距离判断，不能写死在旧基地坐标。

住所被突破时可战斗、撤离或以后回来。设施破坏可产生一次内容掉落，不能无说明随机扣掉库存。不存在核心屋血量归零后强制结束游戏。

### 10.2 尸群与感知（优先）

僵尸按游荡→调查声源→发现目标并追击→失去目标后搜索→放弃返回游荡的流程行动。看不见玩家时不持续读取玩家坐标。枪声、跑步、破窗、警报和发电各自生成AI声音事件；不能用手机扬声器音量控制感知。

墙与门窗影响视线；第一阶段声音按距离和简单遮挡修正，不做复杂声学模拟。消音器降低声源范围但不会完全无声。玩家可绕建筑甩脱敌人或利用其他声源引开尸群。

游荡尸群和警报事件可出现，但不是每晚固定针对玩家住所的进攻。事件需要预兆、合理生成位置和逃离路线；同一事件实体有唯一ID，加载与切图不得重复刷出。第一阶段保留普通、快速、破坏型三类敌人，不新增大量技能怪。

### 10.3 远处地区的处理

附近完整模拟AI与碰撞；较远处降低频率；未加载地区保存快照与上次处理时间。第一阶段不模拟远处住所遭受随机袭击，休眠敌人不会因为“天数增加”自动扣掉玩家库存。已开始的事件需保存阶段，不因切图取消；回访时按已定义规则恢复或结算一次。

食品腐坏、采集恢复和电量等确定性过程可按经过的游戏时间补算；不补算手机关机期间的现实时间。后续若增加跨区尸群迁移，再单独定义低频路线、预算及玩家预警，不沿用旧版离屏攻营地系统。

### 10.4 世界变化（第二阶段）

加入有限地区停电、食物腐坏、天气和补给事件。停电需要预警，不突然删除已存燃料和设备；发电机有燃料和噪声成本。停水与完整电网属于后续，避免第一阶段同时建设复杂基础设施。

保持定居和迁移都可行：搜刮物资有限，采集、雨水、净水和交易提供有成本的长期来源。不能让某地区必然耗尽全部必需资源却又无可达出口。

## 11. 家具、工具与制作

小柜子等先清空再打包，携带受重量与格子限制；可在任意有效地点放下、旋转并继续储物。世界家具、背包家具物品与搬运状态只能存在一份，保留ID、耐久、样式和容器引用。破坏只生成一次材料或内容。

摆放显示碰撞预览，禁止压住角色、穿墙或重叠实体。允许故意封门，但提示可能堵住自己或同伴的出口；敌人可攻击可破坏障碍，队友应改道或报告受阻，不无限撞墙。

第一阶段做小件打包；中件双手搬运、大件拆解、手推车和载具后续评估。

工具以用途标签检查：撬棍辅助开门，锤子加固与拆解，维修工具处理设备。第一阶段工具不磨损；第二阶段统一引入耐久、维修和来源，避免工具耗尽导致必需动作死锁。配方集中配置材料、工具、地点要求、时间、产物和噪声；取消或打断不凭空产出。

## 12. UI与安卓交互

主HUD展示生命、体力、饥渴、疲劳、负重、武器弹药、时间、当前动作与同伴状态，不再显示核心血量或每夜守家倒计时。用状态图标与文字表达威胁，不显示隔墙敌人的精确位置。

| 界面 | 内容与操作 |
|---|---|
| 背包/搜刮 | 自身与附近容器并列，点按转移，批量请求与中断提示 |
| 配件 | 兼容槽、装拆、效果变化和空间不足原因 |
| 地区地图 | 已探索地形、传闻、出口、住所、遗物和待救同伴 |
| 世界地图 | 已知地区与连接；区分未抵达、已抵达和不可通行 |
| 落脚点 | 命名、设为首选恢复点、会合点、取消登记；不远程操作库存 |
| 同伴 | 专长、装备、负伤和短指令 |
| 互动列表 | 明确门窗、床位、工具与动作耗时，避免目标误选 |

横屏适配安全区域，主要触摸热区建议不小于约48dp。视觉图标可小，触摸区不可照搬像素尺寸。摇杆和按钮支持位置、透明度、缩放、锁定与左手模式；多点触控独立跟踪，快捷物品不打断移动瞄准。中文字号可调，物品转移不强迫精细拖拽。


## 13. 像素美术与声音规范

### 13.1 建议初始规格

- 世界采用方格图块，建议先以 32×32 像素地块、约 16×24 至 24×32 的小人物为试制范围；最终以安卓截图可读性确定。
- 使用有限像素密度、最近邻采样和整数倍率优先缩放；不混用高清预渲染人物、不同角度建筑和低清 UI。
- 角色朝向和动作先满足行走、持械、攻击、受击、倒地与死亡；四向起步，八向属于后续统一升级。
- 枪械配件在小人身上只表现可读的主要轮廓，在装备详情中显示完整组合。
- 室内外使用同一套地块比例、碰撞高度与家具占格规则。
- 屋顶隐藏、墙体淡出只改变表现，不改变碰撞、声音和敌人的可见性判断。

### 13.2 声音规则

声音分为玩家可听见的音效和 AI 感知事件。枪声、破窗、近战、警报和设施工作分别定义半径及持续时间，不能依据实际扬声器音量决定 AI 是否察觉。

敌人追向最后感知位置，丢失线索后搜索；不永久知道玩家位置。消音器降低噪声而不消除；视觉发现与声音发现可以分别触发。


## 14. 技术路线与源码改造边界

沿用现有LastCamp的Godot 4.x/GDScript二维工程，安卓横屏arm64。具体引擎版本以导出验证为准，保留现有战斗与触屏能力；不在本次玩法改造中无理由更换引擎。

| 模块 | 职责 |
|---|---|
| 世界/时间 | 唯一时钟、区域连接、发现、事件调度 |
| 地图生成与加载 | 稳定种子、地图ID、区块缓存与入口落点 |
| 感知与敌人 | 视线、声音事件、最后发现位置、调查/追击/搜索 |
| 生存与休息 | 饥渴、体力、疲劳、伤势、睡眠及时间加速 |
| 住所与设施 | 登记点、床位、实体容器、工作台和恢复点有效性 |
| 战斗与装备 | 武器、命中、配件、枪内弹药，不自行修改存档 |
| 物品与行动 | 唯一归属、容量、队列、取消和原子提交 |
| 建筑与家具 | 门窗、遮挡、碰撞、打包和拆解 |
| 同伴 | 指令、救援、会合与离屏任务，避免重复模拟 |
| UI/保存 | UI只提交请求；保存服务持有权威状态与版本 |

现有world_map.gd可扩展为地区地图生成器；world.gd承载的全局状态需增加map_id和分区存储。game.gd中的camp/town切换、营地碰撞、核心失败、固定设施坐标、尸潮目标应逐项替换；survival_systems.gd中的床、商人和发电坐标改为对象查询；world_view.gd与hud.gd删除强制基地展示，增加出口与落脚点反馈。

改动按模块分步实施，不把感知、跨图、睡眠、库存和UI全部塞进一个脚本。保留原有可用功能；改变规则对应的旧测试需更新，不能为通过旧版守家测试重新引入已取消的设定。

## 15. 数据、保存与恢复

### 15.1 数据要求

| 数据 | 必要内容 |
|---|---|
| 世界 | schema_version、world_id、种子、统一时间、已知地区与连接 |
| 地区 | map_id、种子、布局版本、发现状态、上次处理时间、实体变更 |
| 入口连接 | connection_id、两端map_id和入口ID、通行条件、耗时 |
| 玩家/NPC | map_id、位置、状态、装备、任务与会合目标 |
| 物品/容器 | 全局唯一instance_id/container_id、定义、数量、唯一归属和容量 |
| 枪械 | 枪内弹药、弹种、配件实例引用和状态 |
| 家具/门窗 | 唯一ID、map_id、位置、耐久、开关/加固/破损及容器引用 |
| 落脚点 | shelter_id、map_id、床位引用、名称、登记与首选标记 |
| 遗物 | 唯一容器ID、原死亡位置、物品引用，不覆盖其他遗物 |
| 尸群/事件 | event_id、位置或路线、阶段、实体引用及已处理时间 |

### 15.2 事务与兼容

切图时同时提交来源状态、目标加载、玩家与同行者位置、旅行耗时；成功后统一切换，失败恢复原完整快照。跨区ID包含世界/地区身份或采用统一分配，不允许两个地区生成同名容器导致串库存。

死亡、回收、配件装拆、家具转移和关键队列完成采用原子提交。临时文件写完并检查后替换，保留上一份完整备份；继续游戏读最新有效快照，不偷偷回退到清晨。

现有v0.5旧存档迁移建议采用：保留旧town布局、种子和物资状态作为初始地区；旧camp保存为一个可返回的普通历史地区，实体位置与容器归属保留，取消核心和定时来袭功能；原恢复床可转为普通登记点。迁移复制备份，转换后校验全部物品和NPC引用。不能静默删除旧仓库或把满仓库直接塞入背包；若迁移未实现，明确提示旧档暂不兼容并保留原文件，不声称自动迁移成功。

随机生成后的物资和地区结果必须保存。清理纹理/区块缓存不等于删除地区状态。后台不推进现实时间；载入时不重复生成、重复结算或改变已提交的物品归属。

## 16. 阶段范围与交付顺序

### 16.1 第一阶段：可玩的自由探索闭环

| 内容 | 验证边界 |
|---|---|
| 地图 | 两个可往返地区，每区至少一个稳定入口；一条可发现的新地图线索 |
| 建筑 | 三种可进入的一层建筑，有实际搜刮点和撤离路线 |
| 落脚点 | 任意有效床位休息，至少两个可登记点；储物独立持久化 |
| 敌人 | 沿用三类，完成调查、追击、搜索和丢失目标 |
| 门窗 | 开关、破坏、清玻璃、翻越、简单加固与遮挡 |
| 生存 | 基础状态、疲劳、睡眠、流血、打断与唤醒 |
| 武器 | 沿用现有枪械与配件；不因改版删除已可用装备 |
| 家具 | 一个空箱柜打包、跨区携带、放置、储物与阻挡 |
| 同伴 | 最多一名同行，跟随/等待/救起，跨图无复制 |
| 死亡/保存 | 全部掉落、住所恢复、备用位置、遗物回收、跨图事务 |
| UI | 删除强制守家指标，增加地区出口、地图状态与住所管理 |

验收流程：搜刮触发噪声→敌人调查→利用建筑甩脱→选房封窗睡觉→翌日根据线索进入新地区→返回后原房屋和库存仍正确。第一阶段不要求把第二阶段所有生活系统一起完成。

### 16.2 第二阶段：多日生存与内容变化

加入鲜食腐坏、脏水与煮沸/净化、雨水收集、工具耐久、有限制作、腿伤疼痛、地区停电、少量警报和建筑故事组合。至少进行七个游戏日的资源验证：

- 水：可持续取水并处理，存在不会因一次工具丢失就永久失效的最低途径。
- 食物：有限采集点按世界时间恢复，人工与NPC采集共享库存；罐头与鲜食形成携带取舍。
- 材料：拆解有真实对象成本，不允许原家具复生；交易或有限恢复点支持必要维修。
- 弹药：探索、交易与有限事件取得，基本生存不能必须依赖无限开枪。
- 新地区：有不同资源与风险，但不把无限新增地图当作唯一资源平衡方案。

睡眠加速、旅行与恢复均需推进这些过程；腐坏后的物品状态与所有权一致保存。

### 16.3 后续候选

载具驾驶与维修、手推车、中大型家具搬运、多层建筑、农业、更多同伴职责、地区尸群迁移、完整停水电网、职业特质、可选永久死亡与联机。未经单独评审不视为本次改版承诺。

## 17. 性能与质量要求

先指定安卓基准设备记录系统、内存和分辨率。常态争取60FPS，压力场景以可操作30FPS为评估目标，不提前承诺所有手机达标。

按附近区块加载纹理与实体，远处AI分批降频，离开地区释放缓存但保留状态。路径局部更新，避免每只敌人每帧全图寻路。声音事件有有效期、数量限制与空间查询，不向全世界所有僵尸广播。

覆盖30、60、100敌人的梯度压力、区域往返、睡眠加速和长时间游玩；记录内存、温升、帧耗时与加载停顿。未达到上限要如实说明。对象池不得复用正在存档中代表不同物品的实例ID。
